## What I'm building right now

**[`admin-lab`](https://github.com/rauf-babajanov/admin-lab)** — a Windows Server / Active Directory / Entra ID / Intune lab, built from a single Hyper-V host, as hands-on preparation for the **MD-102: Endpoint Administrator Associate** certification.

It's early. Right now it's a repository skeleton, a host decision record, and the first checkpoint closed. What it will become: a domain, a couple of endpoints, some policies I apply correctly and then some I deliberately misconfigure so I can practice diagnosing them properly.

The point isn't to finish fast. It's that every stage gets:

- a short decision record — what I chose and why, not just what I clicked
- evidence that it actually works — command output, not a claim
- when something breaks (on purpose), a real incident writeup: symptom → hypothesis → root cause → fix

Repo is private for now. It goes public once there's enough built to actually be worth reading.

## How I actually work

Not a list of buzzwords — just the habits that show up in the repo itself:

- **I don't call something "working" without proof.** Command output or it didn't happen. Memory isn't evidence.
- **One change at a time, with a way back.** Small, reversible steps beat a big change I can't undo.
- **I diagnose in layers, not guesses.** Network → DNS → auth → policy — in that order, every time.
- **Documentation is part of the build, not cleanup afterward.** If it's not written down, I didn't actually learn it.
